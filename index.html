What is working here

  • Versioned browser ↔ worker messages with structured diagnostics.
  • Inline XForms model discovery into a compact Rust instance snapshot.
  • Opt-in automatic association of unambiguous strict ref paths with compact nodes.
  • Browser model-adapter resolution of discovered XPath 1.0 bind targets to compact element IDs.
  • Transactional Rust scalar values and resolved model-item state.
  • Typed browser-side XPath 1.0 property evaluation over explicit singleton contexts.
  • Opt-in initial bind calculations and model-item projections applied during worker hydration.
  • Conservative static compact-ID dependency extraction with explicit unsupported-reference diagnostics.
  • Strict opt-in singleton calculated-binding recalculation after a source intent.
  • Accessible input, choice, activation, and container components.
  • Opt-in static XForms-markup adaptation for an early presentation subset.

Static XForms-markup adapter

The public adapter converts a deliberately narrow, opt-in subset of xf:* presentation markup to the same component layer. It is not a hidden parser or a full processor.

Scope statement

This site demonstrates an active modernization effort, not a complete XForms 1.1 processor. Inline XML base-state hydration, a compatibility gate, opt-in exact-one strict child-path ref association, discovered bind-target mapping, and opt-in initial calculated/property projections under singleton parent contexts are implemented; general dependency-driven post-intent recalculation, repeat context, actions, submissions, and separately scoped native XPath 2.x / XForms 2.0 semantics remain implementation work; the demonstrated singleton calculated-binding subset is intentionally narrower.

Built from the public demo repository. Browser behavior is exercised in real headless Chromium before publication.
